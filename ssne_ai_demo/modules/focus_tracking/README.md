# 追焦模块

本目录只放追焦功能的板端业务入口和模块私有实现。追焦实时链路全部使用 C++：

- `focus_tracking_main.cpp`：暴露给顶层 `main.cpp` 的功能入口。
- `src/focus_tracker.cpp`：无 NPU 传统视觉追踪实现，以及 MobileNet NPU 模式的接口占位。

运行方式：在主菜单选择 `8. 追焦功能` 后，会进入追焦子菜单：

- `1. 传统视觉追焦`：不加载模型，直接使用 CPU 高帧率模板追踪。
- `2. MobileNet NPU追焦`：预留模型选目标入口，后续加载 `focus_mobilenet.m1model` 后低频调用 NPU，输出 ROI 后由传统追踪器高频接管。
- `0. 返回主菜单`。

子功能运行中按 `Q/q` 只退出当前追焦子功能并返回追焦子菜单；回到追焦子菜单后再输入 `0`，才返回顶层主菜单。

运行时异常处理：

- 公共 `IMAGEPROCESSOR` 维护 `OK / DEGRADED / RECOVERING / FAILED` 健康状态，人脸、目标、表情、手势、追焦等所有使用该图像管线的功能都会自动获得同一套摄像头异常检测和恢复机制。
- 连续取不到有效图像帧时先进入 `DEGRADED`，达到恢复阈值后进入 `RECOVERING` 并自动重开 camera pipeline。
- 公共图像管线会低频采样亮度、过暗比例、过曝比例和纹理强度，检测 `TOO_DARK / TOO_BRIGHT / LOW_TEXTURE` 数据质量异常。
- 在追焦功能中，camera pipeline 重开成功后会额外清空旧追踪目标和 OSD 框，避免用异常前的旧目标继续输出。
- 连续恢复失败会进入 `FAILED`，但仍按退避间隔继续尝试恢复，不因单次异常直接崩溃。
- 顶层主菜单选择功能后会继续选择运行时日志模式：静默、摘要、验证。验证模式输出 FPS/P95/图像质量/恢复统计，静默模式关闭高频运行日志。

追焦鲁棒性：

- 传统追踪器对目标框位置做轻量平滑，降低 OSD 抖动。
- 模板只在匹配置信度和清晰度评分足够时更新，避免暗光、过曝、失焦时污染模板。
- MobileNet NPU 模式连续推理失败会在当前会话内禁用 NPU 选目标，自动回落到传统追踪。

实时运行时不会调用 shell 或 Python 脚本。后续若需要补充脚本，只能作为开发辅助：

- shell：用于板端批量启动、采集样本或整理日志，不参与每帧追焦处理。
- Python：用于 PC 端离线评估、画轨迹图、检查训练数据，不在板端实时路径中运行。

模型文件统一放在 `../../app_assets/models/`，追焦 MobileNet 模型建议命名为 `focus_mobilenet.m1model`。
