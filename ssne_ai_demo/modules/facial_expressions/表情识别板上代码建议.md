# 表情识别板上代码稳定性建议

> 供 WSL 中修改完整 SDK 工程的 agent 参考。本文依据当前仓库
> `onboard/facial_expressions/facial_main.cpp`、
> `onboard/facial_expressions/src/emotion_classifier.cpp` 和
> `onboard/main.cpp`。当前 `onboard/` 快照没有 `common.hpp`、`utils.hpp`
> 及 `RunAiPreprocessPipe` 的实现，修改前需要在完整 SDK 中确认这些定义。

## 一、当前板端流程

当前处理链路为：

```text
摄像头 720x1280 Y8
  -> 固定 ROI：x=40..680、y=320..960
  -> 640x640 Y8
  -> RunAiPreprocessPipe
  -> 112x112 SSNE_RGB（灰度复制三通道，0..255，无手动归一化）
  -> emotion_4class.m1model
  -> 4个 logits
  -> CPU softmax
  -> Argmax
  -> temporal_buffer.Push(emotion, confidence)
  -> GetWeightedVote
```

类别顺序必须保持：

```text
0=SURPRISE，1=HAPPY，2=SAD，3=NEUTRAL
```

训练、校准和上板共同约束：

```text
摄像头单通道灰度经预处理复制为RGB三通道，112x112，输入语义为0..255，不做 /255，
不减均值；校准配置 mean=[0,0,0]、std=[1,1,1]。
```

## 二、当前稳定性问题

### 1. 推理失败会被当成有效分类结果

`RunSingleFrameInference()` 失败时将四类概率全部设为 `0.25`，随后仍执行
`ArgmaxProbsEmotion()`。如果 Argmax 在相同时返回第一个类别，失败帧可能被解释为
`SURPRISE`，并进入时序缓冲区。

这是应当最先修复的问题。

### 2. `CONF_THRESHOLD` 当前为 0

当前代码：

```cpp
const float CONF_THRESHOLD = 0.0f;
```

等于接受所有低置信度结果。背景、运动模糊、过曝、欠曝和无人脸画面都会参与投票。

### 3. 时序滤波只保存离散类别和单个置信度

当前：

```cpp
temporal_buffer.Push(emotion, conf);
```

会丢失其余三个类别的概率。例如：

```text
帧A：[0.40, 0.39, 0.11, 0.10]
帧B：[0.40, 0.10, 0.39, 0.11]
```

两帧都会被压缩成“类别0、置信度0.40”，无法体现模型其实非常不确定。

### 4. 缺少切换滞回

当两个类别概率接近时，单纯滑动投票仍可能在相邻类别间来回切换。表情识别不要求低
延迟，适合增加“候选状态连续确认”和“当前状态最短保持时间”。

### 5. 已分配的帧差缓冲区没有真正用于质量门控

`prev_frame_buf`、`diff_buf` 和 `has_prev_frame` 已经存在，但当前
`emotion_classifier.cpp` 没有利用它们。可以用于检测剧烈运动或画面异常，避免模糊帧
污染时序状态。

## 三、建议的修改优先级

## P0：推理函数返回成功/失败，失败帧禁止进入滤波器

建议将接口改成：

```cpp
bool EMOTIONCLASSIFIER::RunSingleFrameInference(
    ssne_tensor_t* img,
    float out_probs[4]);
```

以下任何情况都返回 `false`：

- `RunAiPreprocessPipe()` 失败；
- `ssne_inference()` 失败；
- `ssne_getoutput()` 失败；
- 输出指针为空；
- 任一 logit 为 NaN/Inf；
- softmax 的和无效。

调用处：

```cpp
float probs[4] = {0.f};
if (!RunSingleFrameInference(img_in, probs)) {
    // 保持上一稳定结果，不向 temporal_buffer 写入均匀概率。
    result->emotion = stable_emotion;
    result->confidence = stable_confidence;
    return;
}
```

不要再用 `[0.25, 0.25, 0.25, 0.25]` 表示推理失败，因为它仍然是一个看似合法的概率
分布。

## P1：保存并滤波完整四类概率

将 `EmotionTemporalBuffer` 从：

```cpp
Push(EmotionClass emotion, float confidence)
```

改成至少接收：

```cpp
Push(const float probs[4], uint64_t timestamp_ms)
```

推荐先使用低成本 EMA：

```cpp
ema[i] = alpha * probs[i] + (1.0f - alpha) * ema[i];
```

初始建议：

```text
alpha = 0.25~0.35
```

若实际帧率不稳定，建议按时间计算 alpha，而不是固定按帧：

```cpp
alpha = 1.0f - expf(-dt_ms / tau_ms);
```

可从以下参数开始：

```text
tau_ms = 350~500 ms
```

这样不同帧率下的平滑时间基本一致。

## P1：增加置信度、概率差和连续帧滞回

同时计算：

```text
top1_prob
top2_prob
margin = top1_prob - top2_prob
```

初始参数建议：

```text
top1_prob >= 0.50~0.60
margin >= 0.10~0.15
候选类别连续出现 3 帧才允许切换
新类别平滑概率至少比当前类别高 0.05~0.10
```

推荐状态机：

1. `stable_class`：当前对外显示类别；
2. `candidate_class`：待切换类别；
3. `candidate_count`：候选连续确认次数；
4. 若新候选不满足阈值，清空候选，但暂时保持当前稳定结果；
5. 同一候选连续满足条件3帧后才更新 `stable_class`；
6. 使用时间而非循环次数限制最短保持时间，例如 `300~500 ms`。

不要简单地把所有低置信度帧强制改成 `NEUTRAL`。这会在真实表情与中性之间产生新的
抖动。低置信度时优先“保持上一次稳定结果”，持续不确定超过约 `800~1500 ms` 后再
回落到 `NEUTRAL`。

## P1：启动预热

滤波器刚启动时没有历史信息。建议：

- 前3～5个有效推理帧只积累概率；
- 达到最小有效帧数后再显示稳定类别；
- 初始化阶段可显示 `NEUTRAL` 或 `UNKNOWN`，不要直接采用第一帧。

退出并重新进入表情识别模块时必须清空：

```text
EMA概率、候选类别、候选计数、稳定类别、时间戳和上一帧缓存。
```

## P2：加入轻量画面质量门控

在送入时序滤波前对 `112x112 RGB` 或 `640x640 ROI` 计算低成本指标。

### 亮度门控

```text
平均灰度过低，例如 < 20
平均灰度过高，例如 > 235
灰度标准差过低，例如 < 12
```

出现上述情况时不要更新状态。

### 运动门控

利用当前已经分配的 `prev_frame_buf` 和 `diff_buf`：

```text
motion_score = mean(abs(current - previous))
```

如果运动分数过高，说明可能正在转头或发生运动模糊，可跳过该帧，等待画面稳定后再
更新。阈值需要使用实际板端视频统计，不能直接写死。建议先记录正常静止、正常表情
变化和快速运动三种情况下的分数，再选阈值。

### 清晰度门控

如果板端 CPU 预算允许，可以计算简化梯度能量或 Laplacian 方差。清晰度明显过低时
跳过状态更新。质量门控只影响滤波器更新，不应终止摄像头或 NPU 流程。

## P2：固定 ROI 外增加有效性判断

当前始终使用固定 `640x640` ROI，没有确认人脸是否真的位于区域中。无人脸时模型仍会
强行输出四类之一。

可选方案，按改动量排序：

1. UI 明确显示固定框，引导用户将脸放入框内；
2. 根据 ROI 的亮度、对比度和运动状态拒绝明显无效帧；
3. 如果工程已有可复用的人脸检测模块，低频运行人脸检测，例如每5～10帧一次；
4. 检测不到人脸时冻结结果，持续超时后显示 `UNKNOWN/NEUTRAL`；
5. 检测到人脸后对人脸框适度扩边并裁成正方形，再缩放到112并复制三通道。

如果改成动态人脸裁剪，训练数据的人脸占比也要同步调整，否则会产生新的域差异。

## P2：确认硬件缩放参数

在完整 SDK 中检查 `RunAiPreprocessPipe` 和 `IMAGEPROCESSOR::Initialize`：

- 摄像头源是否确实为 `SSNE_Y_8`，模型输出 tensor 是否为 `SSNE_RGB`；
- ROI 坐标是否使用 `[x1,x2)`、`[y1,y2)`；
- 是否隐含 mean/std、量程转换或颜色转换；
- 缩放使用双线性、最近邻还是其他硬件插值；
- 输出 stride/pitch 是否等于112，是否包含行对齐填充；
- `create_tensor(112,112,SSNE_RGB)` 的宽高顺序和三通道字节数是否正确。

训练、校准和板端目前都采用 `0..255` 无归一化语义。除非全链路同时修改，否则禁止在
任意一处增加 `/255` 或 `[-1,1]` 映射。

## 四、推荐的后处理伪代码

```cpp
bool ok = RunSingleFrameInference(img_in, probs);
if (!ok || !IsFiniteProbability(probs)) {
    KeepLastStableResult(result);
    return;
}

if (!ImageQualityAccepted(img_in)) {
    KeepLastStableResult(result);
    return;
}

prob_filter.Update(probs, now_ms);       // 对四类完整概率做时间EMA
auto smooth = prob_filter.GetProbs();

int top1, top2;
FindTop2(smooth, &top1, &top2);
float confidence = smooth[top1];
float margin = smooth[top1] - smooth[top2];

if (confidence < CONF_ON || margin < MARGIN_ON) {
    candidate_count = 0;
    if (now_ms - last_valid_ms > UNCERTAIN_TIMEOUT_MS) {
        stable_class = EmotionClass::NEUTRAL;
        stable_confidence = smooth[static_cast<int>(stable_class)];
    }
} else if (top1 == static_cast<int>(stable_class)) {
    candidate_count = 0;
    stable_confidence = confidence;
    last_valid_ms = now_ms;
} else {
    UpdateCandidate(top1);
    if (candidate_count >= SWITCH_CONFIRM_FRAMES &&
        now_ms - last_switch_ms >= MIN_HOLD_MS &&
        smooth[top1] >= smooth[static_cast<int>(stable_class)] + SWITCH_MARGIN) {
        stable_class = static_cast<EmotionClass>(top1);
        stable_confidence = confidence;
        last_switch_ms = now_ms;
        candidate_count = 0;
    }
}

result->emotion = stable_class;
result->confidence = stable_confidence;
```

第一版建议参数：

```text
EMA tau             = 400 ms
CONF_ON             = 0.55
MARGIN_ON           = 0.12
SWITCH_MARGIN       = 0.08
SWITCH_CONFIRM_FRAMES = 3
MIN_HOLD_MS         = 400 ms
UNCERTAIN_TIMEOUT_MS  = 1000 ms
```

这些参数必须根据板端录制序列调节，不应只根据单张验证集准确率决定。

## 五、调试输出建议

不要只打印最终类别和置信度。调试版本建议每隔约200ms打印：

```text
raw_probs=[...]
smooth_probs=[...]
top1/top2/margin
stable_class
candidate_class/candidate_count
brightness/contrast/motion_score
frame accepted/rejected 及原因
```

同时统计：

- 每分钟类别切换次数；
- 一次真实表情变化的平均确认延迟；
- 低置信度帧比例；
- 因亮度、运动、模糊而跳过的帧比例；
- 推理或预处理失败次数。

稳定性验收不要只看“画面看起来不抖”，建议至少检查：

1. 保持同一表情10秒，错误切换次数；
2. 四种表情依次保持3秒，切换延迟和漏切换；
3. 快速转头后恢复，是否能回到正确类别；
4. 暂时离开 ROI，是否出现随机 `SURPRISE`；
5. 暗光和过曝情况下是否冻结而非乱跳。

## 六、最小改动实施顺序

1. 先修复“失败帧写入0.25概率”的问题；
2. 将 `CONF_THRESHOLD=0` 改为概率和 margin 双阈值；
3. `TemporalBuffer` 改为保存完整四类概率；
4. 增加 EMA、候选连续确认和最短保持时间；
5. 增加启动预热与不确定超时回落；
6. 再加入亮度、运动和清晰度门控；
7. 最后根据板端录制数据调参，避免一次同时改动过多而无法定位效果来源。

不建议第一版直接引入 RNN/LSTM。概率域 EMA、滞回状态机和质量门控几乎不占 CPU，
更容易调试，也不会增加模型重新训练和重新量化的成本。
